GOAL — what we are building: a native macOS desktop app that reproduces the OpenAI Codex desktop experience, written in Rust on gpui-kit (gpui-pre + gpui-component). The user talks to a coding agent through a chat interface; the app is the shell around that agent — conversation surface, streaming agent output, tool-call visibility, workspace/session management, and the OS-native chrome that makes it feel like a real desktop product rather than a terminal wrapper.

The bar is the real Codex desktop app: it should look, feel, and behave like it. Not a demo, not a proof of concept — a working product a developer could use daily to run agent sessions against a codebase. Performance, correctness, and polish all matter: streaming must be live, the UI must never block on agent I/O, state must survive restarts, and every interaction must feel native to macOS.

The reference is Codex desktop itself. Do not work from a fixed feature list — there isn't one. Each lane must compare what exists against what the real product does, find the gap that matters most, and close it. If something in the app is a stub, a simulation, a placeholder, or a shortcut that the real product does properly, that is the work. Discover what is missing; do not wait to be told.

Architecture is settled and not up for debate: Rust + gpui-kit, the `AgentBackend` trait as the seam between UI and agent transport, chats persisted under `~/.rixl/rixlcode/`, 250 SLOC per file, conventional commits, `mise run verify` + `mise run lint` green before every merge. Work inside that frame.

TURN MECHANICS per iteration: (1) Collect finished subagents via background_output. (2) Verify each lane (read doc/diff, confirm only Rixl trailer commits), push, PR vs main with falsifiable title/body, rebase-merge when MERGEABLE (never squash, never merge-commit — linear history) (keep-both-sides on trivial conflicts; document-and-leave-OPEN on hard ones). (3) TURN-END RITUAL every turn: ff main, then delete ONLY lane clones/branches whose PRs are confirmed MERGED (check `gh pr view --json state` per branch — never pattern-delete; open-PR branches are spared, no exceptions) by removing the clone dir (`rm -rf /tmp/rixl-rixlcode/<name>`, no `git worktree remove`/prune needed — each clone is an independent copy). End state: everything on main, zero leftover lane-clones/branches, disk freed. (4) MERGE-ORDER GATE: same-module-family code lanes merge sequentially with a check build between; when two lanes touched the same module, run a pre-merge duplicate-symbol grep first; never batch-merge two same-module moves. (5) QUALITY RATCHET: worse-than-before ideas are DROPPED forever; same-as-before recorded but NOT re-laned; only the BEST additional checks are chosen — each wave aims strictly above the last proven outcome. (6) SELF-AUDIT every ~3 turns: find what the loop itself does wrong (stale lanes, weak prompts, missed findings, disk creep) and apply one self-improvement. (7) Keep 6+ lanes in flight, plus one infra/verification lane max per wave. Standing bans: PR+merge only (no direct main pushes), no type suppression, no `#[allow]`/lint-suppression directives of any kind — subagents must fix the flagged functions and files instead of silencing lints, 250 SLOC/file, unit-tests-only for fixes (mocked I/O, no downloads/DB writes outside own temp dirs). LANE PROMPT HYGIENE (mandatory in every lane prompt): narrow grep/sed queries only, never re-read a file after compression — narrow or delegate instead, max 2 re-checks per file without an intervening mutation. ROLLING REFILL (mandatory): process each completion immediately — never wait for all lanes to finish; the moment a lane completes, collect its result and spawn a replacement lane for the next queued task so the in-flight count stays at the target (6+); a free slot with queued work is a loop bug, not a pause point. Always schedule the next run.
